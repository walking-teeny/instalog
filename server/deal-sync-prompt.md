이 작업은 사용자가 사전 승인한 반복 자동화입니다. 확인을 다시 구하지 말고 그대로 실행하세요.

목적: instalog(현재 디렉토리)의 모든 계정에 새로 쌓인 인스타그램 인플루언서 아웃리치 로그(dm_logs)를, 대응하는 fanding-os(본부 OS) 파이프라인에 "딜"로 자동으로 넣습니다.

절차:

1. `npm run sync:find` 를 실행합니다. 이 스크립트는 (계정 구분 없이) 아직 본부 OS로 안 넘어간 로그만, (프로젝트, 단계) 조합별로 그룹핑한 JSON을 출력합니다. 형태:
   `{ "groups": [{ "projectId", "projectName", "pipeline", "stage", "status", "targets": [{ "logId", "name", "url", "kind", "owners" }] }], "unmapped": [{ "projectId", "projectName", "logIds": [...] }] }`
   (같은 프로젝트라도 instalog 소통 상태가 다르면 별도 그룹으로 나뉩니다 — add_deal은 한 번 호출에 stage/status를 하나만 받기 때문입니다.)

2. `groups`와 `unmapped`가 둘 다 비어 있으면(= 새 로그도, 밀린 미매핑 로그도 없음) 아무것도 하지 말고 조용히 종료하세요. `unmapped`에 항목이 있다면 `groups`가 비어 있어도 5번으로 넘어가 반드시 출력하세요 — 그래야 특정 계정의 로그가 계속 미매핑으로 쌓이는 걸 놓치지 않습니다.

3. `groups`의 각 그룹에 대해, fanding-os MCP 커넥터의 `add_deal` 도구를 정확히 이렇게 호출하세요:
   - `pipeline`: 그 그룹의 `pipeline` 값 그대로 (절대 다른 파이프라인을 짐작해서 넣지 마세요)
   - `stage`: 그 그룹의 `stage` 값 그대로 (절대 짐작해서 다른 문자열을 넣지 마세요 — 오타 하나가 새 칸을 만들어버립니다)
   - `status`: 그 그룹의 `status` 값 그대로
   - `targets`: 그 그룹의 targets를 `{ name, url, kind, owners }` 그대로 매핑한 배열 (logId는 add_deal에 보내지 말 것 — 매칭용으로만 쓰세요)
   - `source`: "instalog"
   - **중요**: `name` 등 한글 문자열은 `npm run sync:find`가 출력한 값을 글자 하나도 바꾸지 말고 그대로 복사해서 넘기세요. 유니코드 이스케이프(`\uXXXX`)로 직접 다시 타이핑하지 마세요 — 옮겨 적다 오타가 나면 엉뚱한 글자로 딜이 생성됩니다.

4. add_deal 호출이 성공하면, 그 그룹에 속한 logId들을 모아 `npm run sync:mark -- <logId1> <logId2> ...` 를 실행해 동기화 완료로 표시하세요. 실패한 그룹의 logId는 마킹하지 마세요 (다음 실행 때 재시도되도록).

5. `unmapped`에 항목이 있으면 절대 짐작해서 파이프라인에 넣지 말고 그대로 두세요(마킹하지 마세요). 이때 반드시 다음 형식의 줄을 정확히 그대로 출력하세요(자동화 스크립트가 이 문자열을 찾아서 별도로 알림을 보냅니다):
   `UNMAPPED: <프로젝트명>(<건수>건), <프로젝트명>(<건수>건), ...`
   (여러 프로젝트가 미매핑이면 쉼표로 이어서 한 줄에 모두 적으세요. 프로젝트명은 `unmapped`가 출력한 `projectName` 값 그대로 쓰세요.)

6. 실제로 딜을 추가한 경우에만 어느 파이프라인에 몇 명 추가했는지 한 줄로 출력하세요. 추가한 게 없으면 아무 출력도 하지 마세요.

주의: instalog 자체 DB(dm_logs)의 다른 필드(상태·메모 등)는 절대 건드리지 마세요. "담당 팀"·"회차"는 add_deal에 대응 필드가 없어 반영하지 않기로 결정되었으니 넣지 마세요.
